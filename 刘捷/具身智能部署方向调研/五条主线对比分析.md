# 五条主线对比分析

> 评分对象是“以现有硬件完成一个可交付部署实验”的可行性，不是论文的学术影响力。  
> 评分 1–5 分，5 分最好。“复现难度”分数越高表示越容易复现，避免方向混淆。

---

|---|---:|---:|---:|---:|---:|

## 2. 分维度解释

### 2.1 部署相关性

- **方向 1 = 5**：从模型获取、导出、转换、推理、ROS 2 集成到延迟分析，全链路覆盖。
- **方向 4 = 5**：状态获取、50 Hz 控制、ONNX Runtime、DDS、安全层，是最典型的机器人部署。
- **方向 5 = 5**：TensorRT/量化是部署工程师核心技能。
- **方向 3 = 4**：有分层架构与推理服务解耦，但很容易滑向算法/导航研究。
- **方向 2 = 3**：蒸馏主要是训练侧；如果只做蒸馏训练，部署锻炼有限。

### 2.2 硬件适配性

- **方向 5 = 4**：FP16/INT8 在 Orin NX 上成熟；但 W4A4 插件和 AGX Orin 结果不能直接迁移。
- **方向 1 = 3**：SmolVLA 可能在 Orin NX 上跑，但官方未验证；OpenVLA 7B 不适合 16 GB 统一内存的实时闭环。
- **方向 2 = 3**：学生模型可小，但训练通常在笔记本/服务器，部署不是主要难点。
- **方向 3 = 3**：高层 VLM 可放外部 GPU，底层可上 Orin；但完整 VLN 需要定位、地图、避障。
- **方向 4 = 3**：instinct_onboard 软件栈匹配，但权重缺失、依赖需核对、真机安全风险高。

### 2.3 开源完整度

- **方向 1 = 4**：SmolVLA/OpenVLA 代码、权重、数据生态完整；MiniCPM 官方部署链完整。
- **方向 2 = 3**：Miki 代码可查但依赖旧栈；VITA-VLA 代码链接不完整；Evo-1 代码/权重已开源（需复核具体发布）。
- **方向 3 = 3**：NaVILA/Uni-NaVid 有官方代码；Mobility VLA 更偏研究发布；完整数据/权重需逐项核对。
- **方向 4 = 3**：instinct_onboard 有代码但无权重/License；PredActor 代码未开放；Embrace 项目页有资源但训练栈复杂。
- **方向 5 = 3**：FoldQuant 代码完整但插件重；SQIL 有官方代码；QVLA 有代码但主要是 fake-quant。

### 2.4 复现难度（越高越容易）

- **方向 1 = 3**：SmolVLA 在 LeRobot 中相对容易；但 G1 适配需自己写。
- **方向 4 = 3**：代码可读，但权重/机器人接口/安全是硬门槛。
- **方向 5 = 2**：标准 INT8 容易，论文级 W4A4 很难。
- **方向 2 = 2**：训练资源、教师模型、数据管线都重。
- **方向 3 = 2**：VLN 数据、仿真环境、定位与地图系统复杂。

### 2.5 实时性价值

- **方向 1/4/5 = 5**：都能直接产出 p50/p95 延迟、显存、控制周期抖动数据。
- **方向 3 = 4**：高层频率与底层频率的分离很有价值，但端到端延迟链更长。
- **方向 2 = 3**：主要比较学生/教师推理开销，闭环实时性通常不是重点。

### 2.6 真机价值

- **方向 4 = 5**：直接面向 G1 关节控制与安全闭环。
- **方向 1 = 3**：可做“高层指令→G1 低风险动作”，但端到端 29DoF 不现实。
- **方向 2 = 3**：可把学生模型部署到 G1 感知，但需要数据与训练。
- **方向 3 = 2**：G1 导航需要额外定位、地图、避障和安全策略。
- **方向 5 = 3**：量化本身不产生真机能力，必须依附已有策略。

### 2.7 简历价值

- **方向 1 = 5**：ONNX/TensorRT/ARM64/ROS 2/延迟分析，关键词完整。
- **方向 4 = 5**：真实人形机器人、50 Hz、DDS、安全控制，差异化和说服力最强。
- **方向 5 = 5**：量化、混合精度、显存优化是硬技能。
- **方向 3 = 4**：分层架构与服务解耦有价值，但容易被认为“只是调 API”。
- **方向 2 = 3**：除非有明确蒸馏结果和部署对照，否则容易变成训练实验。

## 3. 三条候选路线独立评价

### 路线 A：端侧轻量 VLA 部署（1 → 5）

**原设想**：先轻量 VLA，再量化优化。

**优点**

- 资料最全，SmolVLA/OpenVLA 可直接获取；
- 能在笔记本完成导出与初步推理；
- 有明确的 FP16/INT8 对照；
- 能形成完整“模型→引擎→ROS 2 节点→延迟”的交付物。

**问题**

- 官方模型输出是机械臂动作，不是 G1 29DoF；
- 若强行端到端控制 G1，需要大量遥操作数据和安全验证；
- OpenVLA 7B 在 Orin NX 上难以达到实时闭环；
- SmolVLA 的异步推理需要 action chunk 与底层控制器配合。

**改造建议**

将路线 A 定义为：

```text
VLA 输出高层动作（前进/转向/抓取目标/技能标签）
        ↓
G1 安全技能层（白名单、限速、限幅）
        ↓
底层控制器
```

这样既保留 VLA 部署价值，又不虚构“端到端人形控制”。

**评分**：部署相关性 5，硬件适配 3，开源 4，难度 3，实时 5，真机 3，简历 5 → **28/35**。

---

### 路线 B：人形机器人机载控制（4b → 4a → 5）

**原设想**：instinct_onboard → PredActor → 量化。

**优点**

- 与 G1/Orin NX/ROS 2 Humble 最匹配；
- instinct_onboard 已有 G1 29DoF、50 Hz、dry-run、关节保护；
- 可直接产出真实控制周期、抖动、延迟数据；
- 简历差异化和真机价值最高。

**问题**

- instinct_onboard 仓库无权重、无 License；没有模型就无法闭环；
- 代码是 Python，不是用户期望的 C++17 核心节点；
- 依赖 `unitree_hg`、`crc_module` 等，需要核对现有 SDK2 环境；
- PredActor 代码未开放，不能直接复现；
- 真机策略测试有摔倒、损坏、伤人风险。

**改造建议**

将路线 B 定义为“**先骨架、后策略**”：

1. 用 dry-run/仿真验证状态—推理—动作维度与关节映射；
2. 用固定姿态/低增益测试安全层；
3. 用公开的G1策略或自己训练的轻量MLP做闭环；
4. 再引入 PredActor 的架构思想或量化。

**评分**：部署 5，硬件 3，开源 3，难度 3，实时 5，真机 5，简历 5 → **29/35**。

---

### 路线 C：算法与系统交叉（2 或 3 → 5）

**原设想**：蒸馏或分层导航 → 量化。

**优点**

- 能训练系统架构与算法能力；
- 分层 VLA 的“高层低频 + 底层高频”非常适合 ROS 2 解耦；
- 蒸馏能补充模型压缩知识。

**问题**

- 蒸馏需要教师模型、训练资源和数据，周期长；
- VLN 需要定位、地图、仿真环境和真实场景，不是单纯模型部署；
- 容易变成“训练/算法研究”，偏离部署工程师定位；
- 量化与蒸馏/导航的耦合验证成本高。

**改造建议**

把路线 C 作为“第二篇论文/拓展”，不要作为首个主项目：

- 方向 3：先做离线协议与仿真，不直接上 G1；
- 方向 2：先做公开数据集上的小规模蒸馏对照，不训练大教师。

**评分**：部署 3–4，硬件 3，开源 3，难度 2，实时 4，真机 2–3，简历 4 → **20–22/35**。

## 4. 路线组合建议

### 推荐主路线：B0 → A1 → Q

```text
B0: G1 部署骨架（dry-run + 状态/动作适配 + 安全层 + 50 Hz 测量）
        ↓
A1: 高层 VLA（SmolVLA）输出技能/waypoint，经安全层执行
        ↓
Q : 对 SmolVLA 做 FP16/INT8 对照，测端到端延迟与任务成功率
```

### 备选路线：B0 → P（PredActor 架构复现/轻量策略）

如果目标是强化“人形实时控制”：

- 先实现一个小的 MLP/GRU 策略，验证 50 Hz 链路；
- 再按 PredActor 论文实现动作扩散（只做离线/仿真）；
- 不依赖未公开权重。

### 不建议作为首项

- 直接复现 FoldQuant 的 W4A4 TensorRT 插件；
- 直接复现 NaVILA 全系统并上 G1；
- 从零训练教师模型做蒸馏；
- 直接把 OpenVLA 7B 部署到 Orin NX 做 50 Hz 闭环。

## 5. 决策矩阵（按目标）

| 目标 | 首选 | 次选 | 原因 |
|---|---|---|---|
| 最快形成部署作品 | 方向 4 骨架 | 方向 1 SmolVLA | 方向 4 不依赖大模型训练 |
| 最强简历关键词 | 方向 1 + 5 | 方向 4 | ONNX/TensorRT/量化关键词密集 |
| 最真实机器人价值 | 方向 4 | 方向 3 | 直接控制 G1 |
| 最容易在笔记本先做 | 方向 1 | 方向 5 | 不依赖机器人 |
| 最偏算法研究 | 方向 2 | 方向 3 | 训练/数据门槛高 |
| 最不建议单独立项 | 方向 5 | 方向 2 | 量化需依附模型；蒸馏周期长 |

---

## 6. 结论

1. **方向 4 是主线，方向 1 是上层，方向 5 是优化层。**
2. 方向 3 适合做架构与仿真，不宜作为首个 G1 真机闭环。
3. 方向 2 适合作为拓展，不应挤占部署主线时间。
4. 初始三条路线都需要修正：
   - A 要改成“高层 VLA + 独立底层控制”；
   - B 要改成“先安全骨架、后策略”；
   - C 要降级为第二项目/拓展。
