# 具身智能模型部署研究资料库

> 面向 **Unitree G1-EDU + Jetson Orin NX** 的论文调研、部署可行性与实验规划  
> 检索截止：2026-11-02  
> 研究定位：不追求从零训练大模型，重点是把已有模型/策略转换、优化、集成到真实机器人闭环中。

---

## 1. 这个资料库解决什么问题

本资料库不以“罗列热门 VLA 论文”为目标，而是回答四个工程问题：

1. 一篇论文的模型究竟输入什么、输出什么，能否脱离原机器人运行？
2. 代码、权重、校准数据、机器人接口和许可证是否足以复现？
3. 在 RTX 4070 Laptop（8 GB）与 Jetson Orin NX（16 GB，TensorRT 10.3）上，哪些环节能跑，哪些必须改？
4. 对现有 G1-EDU，哪项实验能形成“可测量、可演示、可写进简历”的部署成果？

因此，每篇核心论文的笔记都强调 **部署视角**，而不是只复述算法创新。

## 2. 结论先行

### 2.1 五条主线的优先级

| 优先级 | 主线 | 判断 | 主要原因 |
|---|---|---|---|
| P0 | 方向 4：人形机载实时控制 | **最值得先做，但必须从安全骨架开始** | 与 29DoF G1、ROS 2、ONNX Runtime、50 Hz 控制周期直接相关；有开源部署代码可拆解 |
| P1 | 方向 1：端侧轻量 VLA | **适合作为第二条完整闭环路线** | SmolVLA/OpenVLA 生态成熟；但官方均非 G1 策略，需要“VLA 输出高层动作 + 独立底层控制” |
| P2 | 方向 5：低比特量化与混合精度 | **不应独立做，应作为 1/4 的优化阶段** | 真正收益来自整网延迟和任务成功率；FoldQuant 的 TensorRT 插件移植成本高 |
| P2 | 方向 3：分层 VLA 与 VLN | **适合系统架构研究，不适合作为首个真机闭环** | NaVILA/Mobility/Uni-NaVid 的模型与数据门槛高，G1 导航还缺定位、避障与安全层 |
| P3 | 方向 2：感知蒸馏与 Sim-to-Real | **值得读，不建议作为首项工程复现** | 教师—学生训练成本高；Evo-1 属于语义保持而非蒸馏；VITA-VLA 代码资源不完整 |

### 2.2 最推荐的三项实验

1. **G1 机载策略推理与安全控制骨架**  
   参考 `instinct_onboard`，但不直接向真机发送未经仿真的策略动作。先做 dry-run、固定姿态、关节限幅、看门狗、50 Hz 周期抖动测量。
2. **SmolVLA 高层指令闭环（先仿真/离线，后 G1 低风险动作）**  
   验证 VLA 输出动作块与独立底层控制器解耦时的端到端延迟；量化阶段对比 FP16/INT8。
3. **VLA 低比特推理基准（OpenVLA/SmolVLA）**  
   在 RTX 4070 与 Orin NX 上对比 FP16、INT8、W4A4/W8A8 的显存、延迟、动作误差和任务成功率；不把“单帧加速”当作闭环提升。

### 2.3 必须纠正的初始假设

- `MiniCPM-RobotTrack` 是**模型/工程项目**，不是一篇已核实正式发表的论文；官方部署栈主要面向 Go2，输出导航 waypoint，不能直接等同于 G1 关节策略。
- `instinct_onboard` 是**部署仓库**，不是论文；仓库文件树中未发现 ONNX 权重、模型文件或 LICENSE。
- `PredActor` 报告的 Orin NX 16.790 ms 中位数、19.383 ms p95 是**论文报告值**，但官方代码/权重未开放，不能列为“直接复现”。
- `FoldQuantVLA` 的 W4A4 依赖**定制 TensorRT 插件 + CUTLASS**，验证平台是 AGX Orin/Ada，不是 Orin NX；不能把它当作 TensorRT 10.3 原生 INT4 方案。
- `Evo-1` 的核心是**两阶段训练保持语义对齐**，不是知识蒸馏；不能把它归入“教师—学生蒸馏”论文。
- `NaVILA` 是两级架构：VLM 输出中层语言动作，底层运动策略执行；不能简单说成“VLA 直接输出关节动作”。

## 3. 硬件与软件基线

| 项目 | G1-EDU 机载 | 开发笔记本 |
|---|---|---|
| 计算 | Jetson Orin NX，8 核 Cortex-A78AE | i7-13650HX |
| 内存 | 16 GB 统一内存 | 16 GB |
| GPU | Orin NX 集成 GPU | RTX 4070 Laptop，8 GB |
| 系统 | Ubuntu 22.04.5 | Ubuntu 24.04.5 |
| ROS 2 | Humble，CycloneDDS | 可用于仿真/离线工具 |
| CUDA | 12.6 | 13.2 |
| TensorRT | 10.3 | 版本需与导出链单独核对 |
| 架构 | ARM64/aarch64 | x86_64 |

> **关键原则**：笔记本能跑 ≠ Orin NX 能跑；ONNX 能导出 ≠ TensorRT 能构建；TensorRT 能构建 ≠ 闭环能稳定运行。

## 8. 安全声明

本资料库中的任何 G1 控制实验都必须遵循：

1. 先在 Isaac/ mujoco 或 dry-run 中验证输入输出维度、关节顺序、符号和限幅。
2. 真机只允许低增益、低速、吊装/护人条件下的受控测试。
3. 策略节点不得绕过底层安全层直接持续下发未经限幅的关节目标。
4. 必须有独立于推理进程的急停、看门狗、通信超时和关节越限保护。
5. 不把论文中的“50 Hz”当成端到端已达标；必须分别测量推理、传输、控制、执行延迟。
